Software Process Model Analysis & Architecture

An explanation of why the Incremental Model was chosen for GhostRead, and how each development increment maps directly to working software.

A.1 The Access vs. Comprehension Gap

Traditional learning management platforms (such as Moodle, Canvas, and Google Classroom) only record whether a student has accessed a PDF file. Opening a document checks off a requirement, regardless of whether the student actually absorbed the material or scrolled through the entire chapter in 30 seconds.

GhostRead solves this discrepancy by using silent reading-behaviour telemetry — measuring dwell time per section, scroll velocity relative to page text density, and backtracking patterns — to distinguish genuine reading from superficial skimming, and closing the learning loop with targeted micro-assessments on skimmed material.

A.5 Selected Process Model Justification

The Incremental Model was chosen for the following core technical reasons:

  • De-risking the Core Novelty: The comprehension classifier is the riskiest, most novel feature. Developing the reader and event logger first (Increment 1) provides a stable platform and real telemetry data with which to test and tune the classifier in Increment 2.
  • Strict Architectural Dependency: The Targeted Micro-Quiz generator (Increment 3) logically requires the classifier's output to know which sections were skimmed. Quizzes cannot be tested without working classifications.
  • Working Demos at Every Checkpoint: Each increment delivers a fully functional, demo-ready layer that can be demonstrated to an instructor without waiting for the final release.
Why other models were ruled out:
• Waterfall & V-Model: Too rigid; classifier thresholds cannot be perfected upfront without observing actual reading data.
• Pure Agile: Requires continuous customer collaboration and sprint ceremonies that do not apply to a solo student project.
• Spiral: Excessively heavyweight formal risk evaluation overhead designed for multi-million-dollar defense or aerospace systems.

A.6 Incremental Build Breakdown

How each increment was designed, implemented, and verified in this application:

1

Increment 1: Upload + Section Split + Scroll Tracking

Delivers document ingestion (20MB PDF validation, error handling) and page-based section text extraction with word counting. Features a continuous PDF.js viewer with silent viewport dwell and scroll velocity tracking batched every 3 seconds and sent via navigator.sendBeacon.

Traceability: REQ-1.1, REQ-1.2, REQ-1.3, REQ-1.4, REQ-2.1, REQ-2.2, REQ-2.3, REQ-2.4
2

Increment 2: Comprehension Signal Classifier

The core novelty. Runs in under 3 seconds upon session end. Evaluates section dwell against expected reading minimums (words / 3.5 wps * 0.40), relative scroll speed, and backtracking to classify sections as Skimmed, Genuinely Read, or Reread. Stores transparent explanations for every decision.

Traceability: REQ-3.1, REQ-3.2, REQ-3.3, REQ-3.4
3

Increment 3: Targeted Micro-Quiz Generator

Selects ONLY sections marked Skimmed. Skips quiz if 0 sections were skimmed. Generates offline cloze and MCQ questions with in-document distractors in under 5 seconds. Upgrades correctly answered sections from Skimmed to Reinforced.

Traceability: REQ-4.1, REQ-4.2, REQ-4.3, REQ-4.4
4

Increment 4: Comprehension Dashboard + Polish

Provides per-document color-coded heatmaps (Skimmed, Genuinely Read, Reread, Reinforced) with an interactive inspection modal explaining why each label was chosen. Includes a Chart.js historical trend view across reading sessions, loading in under 2 seconds.

Traceability: REQ-5.1, REQ-5.2, REQ-5.3

Behavioral Telemetry Formulation

GhostRead operationalizes reading comprehension through three measurable behavioral dimensions:

1. Expected Dwell Time ($T_{exp}$):
  T_{exp} = W_s / V_{read_base}  (where V_{read_base} = 3.5 words/sec ~ 210 WPM)
  T_{min} = max(2.0s, T_{exp} * 0.40)

2. Relative Scroll Speed Ratio ($R_v$):
  V_{scroll} = ΔY / Δt  (pixels per second)
  D_{text} = W_s / H_{page}  (words per pixel)
  R_v = V_{scroll} / (H_{page} / T_{exp})

3. Classification Heuristic:
  If (Pass > 1 and Dwell_{pass2} >= 4.0s) → Reread
  Else If (R_v >= 1.25 and Dwell < T_{min}) → Skimmed
  Else If (Dwell >= T_{min}) → Genuinely Read
